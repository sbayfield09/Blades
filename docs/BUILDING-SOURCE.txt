Blades 0.50 complete source and FFmpeg relink instructions

This archive contains the application source, embedded font, GLSL shaders,
MIT/GPLv3/STB/artwork/font notices, original FFmpeg 2.8.22 source archive, xsdk changes
to FFmpeg, pinned xsdk source, tests/synthetic WMV/MP4, and premade artwork ZIP.
The proprietary stock Xbox firmware, uploaded reference videos and personal
logs/settings are NOT included. No Microsoft XDK or Simple360Player is needed.

Prerequisites on Linux/Debian: GCC/G++, make, CMake >=3.25, Python >=3.11 with
supported tar extraction filters, git, patch, bison, flex, texinfo, GMP/MPFR/MPC
development headers and glslang-tools. SDL3/EGL/GL headers are needed only for
the desktop preview/tests. Follow dependencies/xsdk/docs/GETTING_STARTED.md for
the free powerpc-xsdk-elf GCC 15.3 toolchain. Its compiler ABI must match xsdk.
The SDK's toolchain builder verifies pinned binutils/GCC/newlib source hashes;
it may download these free sources. This source archive does not include a
precompiled compiler or a proprietary SDK.

Xbox rebuild / relink (from the archive's Blades directory):

  export XSDK_ROOT="$PWD/dependencies/xsdk"
  export XSDK_TOOLCHAIN="$HOME/xsdk-gcc"
  # If no xsdk toolchain is installed, build it first:
  PREFIX="$XSDK_TOOLCHAIN" WORK="$HOME/xsdk-gcc-work" JOBS=4 bash "$XSDK_ROOT/tools/toolchain/build.sh"
  bash tools/build-xbox.sh

The script builds the SDK library/shader compiler, extracts the pinned FFmpeg
archive, applies third_party/ffmpeg/patches/xsdk.patch, copies third_party/ffmpeg/xenon into libavcodec/xenon and builds GPLv3
static libraries including the ported Simple360Player kernels, compiles the application and links them into default.xex.
It also verifies the XEX and makes a complete USB ZIP using the included artwork.
No converter is needed. No Players directory, adapter or sideload.ini is used.
SDK source commit: 5f6dc726f65f6d171493a3628c2415c03551f27b.
See third_party/ffmpeg/README.md for FFmpeg source provenance and exact hash.

To modify/relink FFmpeg:

1. Extract third_party/ffmpeg/ffmpeg-n2.8.22.tar.gz into a directory you choose.
2. Apply third_party/ffmpeg/patches/xsdk.patch with patch -p1 there, and copy
   third_party/ffmpeg/xenon to libavcodec/xenon; edit freely.
3. The generated build/ffmpeg-xbox-v043-final/objects/blades-configure.txt records every
   configure option from the standard build. Run that source's configure in a
   fresh objects directory with the same options, adjusting --prefix to your
   own install directory; then make -j4 and make install. You can alternatively
   edit the extracted standard build/ffmpeg-xbox-v043-final/source/FFmpeg-n2.8.22 sources
   after the first build and run make -C build/ffmpeg-xbox-v043-final/objects install.
4. Set BLADES_FFMPEG_PREFIX to that install directory and run tools/build-xbox.sh.
   The application recompiles/relinks against your replacement static libraries.
   Modifications/debugging for the LGPL library are permitted. FFmpeg version/API
   changes may also require changing src/core/video.c. The source archive hash
   check in the automated builder protects the original archive, not your own
   modified-library route.

Host decoder/UI tests (with SDL3 installed):

  python3 tools/build-video-ffmpeg.py --target host --build build/ffmpeg-host
  cmake -S . -B build/linux -DCMAKE_BUILD_TYPE=Release -DBLADES_FFMPEG_PREFIX="$PWD/build/ffmpeg-host/install"
  cmake --build build/linux -j4
  BLADES_RESOURCE_PACK="$PWD/dist/Blades/Assets/blades.xzp" ctest --test-dir build/linux --output-on-failure

For full resource/GPU tests first unzip dist/Blades-artwork-pack.zip to a temporary
location and copy its Assets/blades.xzp into dist/Blades/Assets/. Add
-DBLADES_GPU_CHECKS=ON to CMake and EGL_PLATFORM=surfaceless for a headless Mesa
GPU test. The embedded-engine test consumes tests/media/sample.wmv and sample.mp4 plus the1080p MPEG2/720p H264 fixtures.
Leak detection is disabled in the cloud's traced executor; ASan/UBSan covered the
application wrapper. The prebuilt FFmpeg libraries were not sanitizer-instrumented.
These host tests do not establish Xbox runtime behaviour or performance.

Vector arithmetic check:
  python3 tools/test-simple360-dsp.py <FFmpeg-build-directory> --qemu <qemu-ppc>
It uses an independent scalar interpolation oracle. tests/test_simple360_reference.c
separately validates that oracle against FFmpeg's own scalar functions, linking
libavcodec/libavutil with the decoder's extracted internal headers.
The temporary PPC harness uses the same GCC vector source, with test-only
store-merging disabled and32-bit stack-save/pointer-extension ABI adaptation.
Production objects are not edited. This does not measure Xbox timing.

Blades0.50 enables vectors ONLY in its two Simple360 H264 filter objects.
Generic FFmpeg PPC/AltiVec and compiler vectorization stay disabled. Run
  python3 tools/verify-video-decoder.py <FFmpeg-build> --objdump <toolchain-objdump>
to audit all five decoder libraries. Run tools/test-gpu-shaders.py XSDK_ROOT
build/xbox/default_shaders.h for actual compiled shader arithmetic/samplers.
These arithmetic checks do not execute console GPU hardware.

The default decoder build is build/ffmpeg-xbox-v043-final. Pacing tests use a
separate slow-decoder library with BLADES_VIDEO_TEST_DECODE_NS; that macro is
absent from the captured and Xbox shipping builds. The combined binary is GPLv3;
COPYING.GPLv3 and all original source/artwork/font notices are included.

Jellyfin0.50 seeking/resume and Next Up/Continue Watching use the preserved/ported XenonFin native protocol/JSON/browser
sources under third_party/xenonfin (GPL-2.0-or-later, combined under GPLv3),
BSD socket adapter and workers/UI/tests. No FFmpeg-network, curl or new SDK
binary is required. Native source rebuilds against the same verified0.43
FFmpeg libraries; the builder's default remains ffmpeg-xbox-v043-final.

The local network fixture requires Python3 and installed ffmpeg:
  ctest --test-dir build/linux --output-on-failure -R jellyfin
For optional real-server integration, download the checksum-pinned test server:
  python3 tools/fetch-jellyfin-test-server.py /path/to/test-server
  JELLYFIN_TEST_SERVER=/path/to/test-server/jellyfin python3 tests/test_jellyfin_real.py
It creates/deletes only its own disposable account/media/config. --record also
captures the shared renderer against that temporary server. No account data
or test-server binaries are packaged. Normal builds do not need that server.

Use --seek-content with tests/test_jellyfin_real.py for actual frame-coded seek
verification against the disposable official server. It checks source pictures,
not only the player's rebased clock. No user media or settings are needed.

Version0.50 adds bounded authenticated PNG artwork transport/decode, a debounced
selection worker/cache and right-side metadata rendering. Native XAM startup
buffers and FTP bulk POSIX I/O/control replies are tuned; no new SDK dependencies.
Optional desktop FTP comparison:
  python3 tests/benchmark_ftp.py /path/to/old-fixture build/linux/blades-ftp-fixture
These local measurements do not establish hardware speed.

Version0.50 adds the dedicated update HTTPS worker and bundled Mbed TLS3.6.5
source/config, public CA roots and the root-header embedding script. All are
built by CMake for desktop/Xbox; no TLS binary download or new SDK is needed.
The updater uses XeCryptRandom on Xbox and portable scalar crypto, independent
of the video/Jellyfin path. tools/publish-release.py prepares and publishes the
verified Release assets/update manifest. See UPDATES.md.
